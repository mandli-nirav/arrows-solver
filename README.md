# Arrows Solver

An open-source Android helper for the puzzle game **Arrows – Puzzle Escape** (`com.ecffri.arrows`).
A floating bubble sits over the game. **Analyze** reads the level from the screen; **Solve** clears it one arrow at a time
and stops the moment anything looks wrong, so it never spends your lives.

> Unofficial fan project. Not affiliated with, endorsed by or connected to the game's developer.
> It does not modify the game, remove ads or unlock purchases. It contains no game code or game assets:
> the level data is generated locally from **your own** installed copy (see below).

**Status: works but not finished.** It has cleared full Hard levels without losing a life, but some boards still make it stop
for safety. See [Known issues](#known-issues). Contributions are welcome.

## How it works
- **Accessibility service** (`SolverService.kt`): the floating bubble and panel (`TYPE_ACCESSIBILITY_OVERLAY`, no "draw over apps"
  permission), screenshots via `takeScreenshot` (Android 11+), taps and two-finger pans/pinches via `dispatchGesture`.
- **Vision** (`Vision.kt`): finds the cell grid from line projections, reads lines, arrowheads and the "emptied" dots,
  and stitches panned screenshots together.
- **Level lookup** (`LevelDb.kt`): matches what is on screen against the game's own levels (`assets/levels.bin`, generated by you).
  Arrowheads vote for level, mirror and position; then every visible cell is checked. If nothing matches, it falls back to reading the
  whole board from the screen.
- **Solver** (`Board.kt`, `Engine.kt`): an arrow can leave when the straight line from its head to the edge is empty. Before **every**
  tap the screen must match the model exactly, nothing may be moving and the hearts must be intact.
- **React Native** setup screen (`App.tsx`) styled like the game; bridge in `SolverModule.kt` (TurboModule, `specs/NativeSolver.ts`).

The game's rules, touch handling and camera limits that the solver depends on are written up in
[docs/GAME_INTERNALS.md](docs/GAME_INTERNALS.md).

## Build
Requirements: Node 22+, JDK 17+ (Android Studio's JBR works), Android SDK with platform 37, an arm64 Android 11+ phone.

```sh
npm install
# 1. Generate the level database from YOUR copy of the game (optional but strongly recommended)
adb shell pm path com.ecffri.arrows                  # prints .../base.apk
adb pull <that path> game.apk
pip install UnityPy
python tools/extract_levels.py game.apk              # writes android/app/src/main/assets/levels.bin
# 2. Build and install
cd android
./gradlew assembleRelease                             # Windows: gradlew.bat assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```
Then open **Arrows Solver**, turn on **Bubble service** (Settings → Accessibility). If the switch is greyed out, open App info →
⋮ → *Allow restricted settings* first.

## Use
1. Start a level in Arrows and tap the blue bubble.
2. **Analyze**: green arrows can leave now, orange are blocked. **Map** shows the whole level.
3. **Solve**. Keep your hands off the screen while it runs (a touch cancels its gestures). **Stop** works at any time.

## Known issues
- On some Super Hard boards Solve stops with "Screen doesn't match the plan" because one arrow on screen sits one row away from the
  level data (see the end of [PROGRESS.md](PROGRESS.md)). The special arrow (`SpecialArrowId`) may behave differently. Needs investigation.
- The game zooms out to at most 27 cells across on a 9:20 phone, so wide boards need panning; panning near the end of a level is
  the least reliable part.
- Colours and the left edge-handle area were measured on a Nothing Phone (1). Other phones, light mode and other themes are untested.
- Diagonal ("Diag") levels only work through the level lookup, not the screen-reading fallback.

## Debugging
Nothing about a level is kept on the phone. Only when something goes wrong, the error and the debug lines leading up
to it are appended to `errors.log`:
`adb shell cat /sdcard/Android/data/com.arrowssolver/files/errors.log`
Git Bash on Windows needs `MSYS_NO_PATHCONV=1` for that path.

`prototype/` holds the original Python version (adb + screenshots) that solved the first level; it's handy for trying ideas quickly.
